Roadmap Demo — Scenariul de Demonstrație Obligatoriu (Cap. 8 din Caiet)

Structură de lucru pentru construirea prototipului funcțional care acoperă exact cele 5 scenarii de demonstrație cerute de Autoritatea Contractantă — bază reutilizabilă și scalabilă către Roadmap-ul PM complet (13 module, 24 luni).

De ce contează: conform Cap. 8 + Cap. 9.VI din caiet, oferta tehnică trebuie însoțită de o înregistrare video a acestor 5 scenarii demonstrate punct cu punct. Dacă oricare cerință nu poate fi demonstrată, oferta este respinsă ca neconformă. Acesta este motivul pentru care începem lucrul de aici, nu de la cele 13 module ale platformei complete.

Scenariile nu cer configurarea proceselor specifice ANS, ci doar funcționalitățile de bază standard ale platformelor ofertate (Cap. 8, ultimul paragraf). Practic: construim un prototip generic, funcțional, care acoperă exact pașii ceruți — nu întreaga platformă ANS.

2. Reguli obligatorii pentru înregistrarea video

  • Captură ecran complet — câmpuri și butoane vizibile și lizibile
  • Mișcări mouse lente, urmăribile
  • Narațiune audio sincronizată cu acțiunile de pe ecran, pentru fiecare pas
  • Fișier redabil pe Windows 10 + Windows Media Player (format compatibil, ex. MP4/H.264)
  • Se încarcă în SEAP odată cu oferta — fără link-uri externe/streaming
  • Fiecare cerință din scenarii trebuie demonstrată explicit, punct cu punct (nu prezentare generală)
  • Posibilă reluare online a sesiunii, la cererea Autorității Contractante, în etapa de evaluare

3. Cele 5 Scenarii Obligatorii

1Portal / DMS / Registratură / Workflow

Cel mai amplu scenariu — validează întregul ciclu formular public → înregistrare → workflow → răspuns semnat electronic.

  1. Form Builder: creare formular nou din interfața de administrare
  2. Logică condițională (câmp selector → câmpuri dinamice)
  3. Mapare câmpuri formular → entitate internă „Cerere"
  4. Publicare instant formular pe Portal (sync real-time)
  5. Diferențiere acces autentificat/neautentificat pe Portal
  6. Completare formular cu validări + trimitere
  7. Creare automată „Cerere" în Back-Office + notificări
  8. Registratură: nr. înregistrare automat, metadate, atașamente
  9. Inițiere workflow direct din registratură
  10. Motor workflow: rutare automată, termene, diagramă vizuală
  11. Editor colaborativ documente (track changes, comentarii @user)
  12. Generare răspuns oficial din template + flux aprobare
  13. Semnătură electronică + publicare răspuns + notificare email
→ Modul platformă: Portal Public + Registratură/DMS

2Business Intelligence

Dashboard-uri + interogare în limbaj natural.

  1. 3–4 dashboard-uri: conformitate/termene, flux documente, workload (date pot fi simulate)
  2. NL2SQL: întrebare în română → interogare generată/sugerată → rezultat tabelar/grafic
  3. Salvare rezultate/grafice în zonă de rapoarte/widget-uri reutilizabile
→ Modul platformă: Rapoarte Business Intelligence

3Chatbot / Asistent Virtual AI

Cont, roluri, documente, template-uri, conversații, voce, generare documente.

  1. Înregistrare + autentificare cont nou
  2. Roluri admin vs. utilizator standard (acces diferențiat)
  3. Upload document + procesare automată de către AI
  4. Template documente cu variabile ({{NUME}}, {{CNP}}...)
  5. Gestionare variabile (creare/editare/ștergere)
  6. Conversații: creare, mesaje, redenumire, ștergere, căutare
  7. Upload fișiere în conversație + extragere informații
  8. Mesaje vocale → conversie speech-to-text → procesare AI
  9. Generare document prin conversație (preview + completare variabile)
  10. Notificare documente suplimentare necesare + upload direct
  11. Text-to-Speech pe răspunsurile AI
→ Modul platformă: Chatbot/Asistent Virtual

4Securitate / IAM

Fundația transversală — se construiește prima, o folosesc toate celelalte scenarii.

  1. Identity service: CRUD conturi + grupuri
  2. Fluxuri autentificare configurabile: parolă, 2FA (SMS/OTP), eIDAS/ROeID (mock), politici sesiune/parolă
  3. RBAC granular pe resurse/acțiuni cu roluri predefinite/personalizate
  4. Audit trail imuabil + filtrare/căutare avansată
  5. Secret Manager pentru chei API/certificate/credențiale
→ Cerință transversală: 4.10.1 Managementul utilizatorilor

5LMS (platforma CNFPA)

Asistent de învățare AI + CMS + colaborare + experiența cursantului.

  1. Asistent voce-text RO + bază de cunoștințe interogabilă
  2. Adaptare model de limbaj + intenții (intents) personalizate
  3. RBAC: creare utilizator cu rol (Autor/Evaluator), blocare/deblocare cont
  4. Configurare motor AI (cheie API prin Secret Manager, model implicit)
  5. Audit & securitate: filtrare jurnale, simulare evenimente
  6. CMS: creare proiect, generare AI a structurii materialului, editor drag-and-drop
  7. Asistență AI: rescrie/extinde/rezumă text + Text-to-Speech
  8. Colaborare: co-autor, comentarii contextuale, rubrică evaluare
  9. Responsive: Desktop/Tabletă/Mobil + mod Previzualizare
  10. Experiența cursantului: reluare curs de unde a rămas (sync cross-device)
  11. Evaluări + „Barieră Logică" (blocare avansare fără scor minim)
→ Modul platformă: CNFPA

4. Arhitectură Tehnică Propusă (Prototip Demo)

Stack ales: Node.js + React + PostgreSQL — rapid de dezvoltat, ușor de rulat local/pe un server accesibil prin HTTP, aliniat cu cerințele API-first din caiet.

Frontend — React (Vite) + TypeScript

Portal public (formulare, autentificare) Back-Office (registratură, workflow, editor documente) Dashboard BI (grafice + NL2SQL) UI Chatbot (chat, upload, voce) UI LMS (CMS, player curs, evaluări) Admin IAM (utilizatori, roluri, audit)
▼ REST API (OpenAPI) + JWT/OAuth2

Backend — Node.js (Express/NestJS)

Modul IAM (auth, RBAC, audit, secrets) Modul DMS (formulare, registratură, workflow engine) Modul BI (ETL simplu, NL2SQL prin LLM local/API) Modul Chatbot (conversații, STT/TTS, generare documente) Modul LMS (cursuri, CMS, evaluări)
▼

Date & Storage

PostgreSQL (date structurate, audit log) Object storage local/S3-compatible (documente, fișiere) Redis (sesiuni, cache, cozi mesaje)
▼

Infrastructură Demo

Docker Compose (rulare locală, un singur „docker compose up") HTTP accesibil local (localhost) sau pe un server de test CI simplu (lint + build) — GitHub Actions
